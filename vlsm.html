// 03 — SUBNETTING A SUBNET

VLSM — Variable Length Subnet Mask

Instead of one mask for the whole network, VLSM lets you apply a different mask to each segment — sized to how many hosts that segment actually needs, so no address space is wasted on point-to-point links that only ever need 2 hosts.

Largest segment first 2ʸ − 2 = hosts Classless routing required No overlapping blocks
§1

Classful routing vs. VLSM / classless routing

Classful routing

Only allows one subnet mask for all networks in the design — simple, but wasteful when segments have very different host counts.

VLSM & classless routing

The process of subnetting a subnet. More than one subnet mask can be used across the same major network, giving far more efficient use of IP addresses than classful addressing.

CLASSLESS ROUTING PROTOCOL CHARACTERISTICS Routing updates include the subnet mask  ·  Supports VLSM  ·  Supports route summarization
§2

The VLSM process, end to end

1

Sort segments

Find the segment with the largest number of connected hosts — sort every segment from highest to lowest.

→
2

Mask the largest

Find an appropriate subnet mask for the largest segment.

→
3

Write it down

Write the subnet addresses that fit that mask, and claim one for the segment.

4

Re-subnet leftovers

Take one of the newly created (still-unused) subnet addresses and apply a new, more appropriate mask to it.

→
5

Write it down again

Write the subnet addresses that fit the new mask.

→
6

Repeat

Repeat from step 4 for every remaining, smaller segment.

§3

The 3-step method (per segment, given a host requirement)

1 Determine number of hosts, convert to binary 2 Reserve bits in the subnet mask, find the increment 3 Use the increment to find that segment's network range

This is the same 3-step shape used in classic subnetting — the only difference is that VLSM runs it once per segment, largest first, instead of once for the whole design.

§4

"Why???" — the gotcha everyone misses

Looking only at the /30 requirement in isolation, blocks like 192.168.1.8/30, .12/30, .16/30 … look perfectly valid — they satisfy "2 hosts" just fine. So why did the worked example skip straight to 192.168.1.224/30?

BECAUSE THE SPACE IS ALREADY SPOKEN FOR Addresses 192.168.1.8 and 192.168.1.12 fall inside 192.168.1.0/25 — the block already reserved for the 120-host segment. Likewise, a /27 candidate at .32 falls inside the /26 already reserved for the 60-host segment. Once a larger block is committed, every address inside it is off-limits — VLSM must always carve the next available block after everything already assigned, never any arbitrary block that merely satisfies the size requirement.

This is exactly why VLSM is done largest segment first: it guarantees each smaller mask you introduce afterward only ever eats into space nobody has claimed yet.

§5

Summary

Host formula

2ⁿ − 2 = hosts

Use this to size the mask for any segment's host requirement.

Order of operations

Always start with the segment that has the largest number of hosts to accommodate, then work down.

Classless vs. classful

Classless (VLSM) subnetting sizes masks around hosts; classful subnetting sizes a single mask around a target number of subnets.

§6

Self-check

Why must VLSM be worked from the largest host requirement down to the smallest?
So that every later, smaller subnet is carved from address space that hasn't already been committed to a larger block — reversing the order risks overlapping allocations.
A segment needs 14 hosts. What mask and increment do you use?
4 host bits (2⁴ − 2 = 14) → mask 255.255.255.240 /28, increment 16.
What does a classless routing protocol carry in its updates that a classful one doesn't?
The subnet mask — which is exactly what makes VLSM and route summarization possible.
True or false: VLSM uses the same subnet mask everywhere in the network.
False — that's classful subnetting. VLSM's whole point is applying a different mask per segment based on that segment's actual host count.
